# Spec

The spec is the shared source of truth for all four clients. It holds the rules, worked examples and test vectors. The pages in this section are ported from the [selcom-spec](https://github.com/selcom-developers/selcom-spec) repository at tag `v0.1.0`.

If a client and the spec disagree, the client is wrong, or the spec needs a fix that every client then picks up.

> **Not official.** The spec is not affiliated with, endorsed by or supported by Selcom Paytech Ltd. Where it and [Selcom's developer portal](https://developers.selcommobile.com/) disagree about the API itself, the portal wins.

## Test vectors

The spec repository also holds test vectors that every client must pass:

- [`vectors/signing.json`](https://github.com/selcom-developers/selcom-spec/blob/v0.1.0/vectors/signing.json): signing cases and rejects.
- [`vectors/responses/`](https://github.com/selcom-developers/selcom-spec/tree/v0.1.0/vectors/responses): response fixtures and webhook samples.
- [`tools/`](https://github.com/selcom-developers/selcom-spec/tree/v0.1.0/tools): the Python reference implementation.

All credentials in the vectors are sample values or made up. None of them works against the gateway.
